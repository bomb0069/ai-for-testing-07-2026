🎯 Agent Skills คืออะไร?

🎚️ 3 ระดับของ Progressive Disclosure

🟢 ระดับ 1: Metadata (โหลดเสมอ) ▼

สิ่งที่โหลด: ชื่อและคำอธิบายของทักษะเท่านั้น

# ไฟล์: SKILL.md --- name: "postgres-admin" description: "จัดการ Cloud SQL PostgreSQL: สร้าง instance, backup, monitoring" trigger_keywords: ["database", "postgres", "cloud sql"] ---

Token Usage: ~50-100 tokens ต่อทักษะ

วัตถุประสงค์: ให้เอเจนต์ "รู้ว่ามีความสามารถนี้" และตัดสินใจได้ว่าควรใช้เมื่อไหร่

🟡 ระดับ 2: Instructions (โหลดเมื่อเรียกใช้) ▼

สิ่งที่โหลด: เนื้อหาหลักของ SKILL.md เมื่อเอเจนต์ตัดสินใจใช้ทักษะนั้น

## ขั้นตอนการสร้าง Cloud SQL Instance 1. ตรวจสอบโควต้าโปรเจกต์ด้วย `gcloud compute regions list` 2. ใช้คำสั่ง `gcloud sql instances create...` 3. ยืนยันการตั้งค่ากับผู้ใช้ก่อนดำเนินการ

Token Usage: ~300-800 tokens

วัตถุประสงค์: ให้แนวทางปฏิบัติที่ชัดเจนสำหรับงานนั้นๆ

🔴 ระดับ 3: Resources (โหลดเมื่อจำเป็นลึก) ▼

สิ่งที่โหลด: ไฟล์ในโฟลเดอร์ย่อยเฉพาะเมื่อเอเจนต์ร้องขอ

skills/postgres-admin/ ├── SKILL.md ← ระดับ 2 ├── scripts/ │ ├── create-instance.sh ← โหลดเมื่อต้องการรัน │ └── backup-db.sh ├── references/ │ ├── api-reference.md ← โหลดเมื่อต้องการดูรายละเอียด │ └── troubleshooting.md └── assets/ └── architecture.png ← โหลดเมื่อต้องการอธิบายด้วยภาพ

Token Usage: แตกต่างตามไฟล์ (500-5,000+ tokens)

วัตถุประสงค์: ให้ข้อมูลสนับสนุนแบบ "พอดีเวลา" (Just-In-Time)

⚡ วงจรการทำงาน JIT

1️⃣ เริ่มต้นเซสชัน └─→ โหลดแค่ชื่อ + คำอธิบายของทุก Skill (~100 tokens/ทักษะ) 2️⃣ ผู้ใช้ถาม: "ช่วยสร้าง Cloud SQL instance ให้หน่อย" └─→ เอเจนต์สแกน metadata → พบว่า "postgres-admin" เกี่ยวข้อง 3️⃣ เอเจนต์ร้องขอ: activate_skill("postgres-admin") └─→ ระบบแสดงยืนยันให้ผู้ใช้กดยอมรับ (ความปลอดภัย) 4️⃣ ผู้ใช้อนุญาต → โหลดระดับ 2 (Instructions) └─→ เอเจนต์อ่านขั้นตอน → ตัดสินใจเรียกสคริปต์จากระดับ 3 ถ้าจำเป็น 5️⃣ ทำงานเสร็จ → ผลลัพธ์กลับสู่ผู้ใช้ └─→ เก็บผลลัพธ์ในบริบท แต่ไม่จำเป็นต้องเก็บทั้งสคริปต์

📈 มาตรฐาน Agent Skills กำลังกลายเป็น De Facto Standard ▼

มาตรฐาน Agent Skills (SKILL.md format) กำลังถูกยอมรับเป็นมาตรฐานกลางสำหรับ AI coding agents ทำให้สามารถเขียน Skills ครั้งเดียวและใช้งานได้หลายแพลตฟอร์ม

  • Claude Code ใช้เป็นมาตรฐานหลัก
  • GitHub Copilot รองรับแล้ว
  • Cursor รองรับพร้อมฟีเจอร์เพิ่ม
  • Gemini CLI กำลังพัฒนาให้รองรับเต็มรูปแบบ (PR #23090)
🔄 Progressive Disclosure Level 3 กำลังถูกพัฒนา ▼

ทีม Gemini CLI มี PR กำลังพัฒนาเพื่อเพิ่มการรองรับระดับ 3 แบบเต็ม (Semantic Folder Interpretation) ซึ่งจะทำให้:

  • ตีความ scripts/ = executable อัตโนมัติ
  • ตีความ references/ = docs อัตโนมัติ
  • โหลดทรัพยากรแบบ Just-In-Time แบบสมบูรณ์
  • รองรับ allowed-tools field สำหรับจำกัดสิทธิ์
🌐 Cross-Platform Skills将成为主流 ▼

ในอนาคต การเขียน Skills ที่ใช้ข้ามแพลตฟอร์มได้จะเป็นทักษะสำคัญ:

  • เขียน SKILL.md ตามมาตรฐานกลาง
  • หลีกเลี่ยงฟีเจอร์ที่ยังไม่รองรับทุกที่
  • ใช้ MCP สำหรับ integration ภายนอก
  • ทดสอบบนหลายแพลตฟอร์มก่อนเผยแพร่

❓ FAQ & Troubleshooting

Q: ทำไม Gemini CLI โหลดไฟล์ทั้งหมดแทนที่จะโหลดแค่ไฟล์ที่ต้องการ? ▼

A: เพราะ Gemini CLI ยังไม่รองรับ Semantic Folder Interpretation (ระดับ 3 แบบเต็ม) วิธีแก้:

  1. เขียนคำชี้แจงให้ชัดเจนใน SKILL.md ว่าไฟล์ไหนควร "อ่าน" หรือ "รัน"
  2. ใช้ gemini-cli-skillz extension เพื่อเพิ่มความสามารถนี้
  3. ใช้ MCP servers สำหรับจัดการไฟล์แทน
Q: จะตรวจสอบว่า Skills โหลดสำเร็จหรือไม่? ▼

A: ใช้คำสั่งเหล่านี้ใน Gemini CLI:

gemini mcp list # ดู MCP servers ที่เชื่อมต่อ gemini skills list # ดู skills ที่โหลดอยู่ /mcp list # Slash command ในเซสชัน /skills list # Slash command ในเซสชัน
Q: Token Cost ประหยัดได้จริงแค่ไหน? ▼

A: จากกรณีศึกษาจริง:

  • แบบเดิม: 20,000 tokens ต่อเซสชัน
  • Progressive Disclosure: 2,000-3,000 tokens ต่อเซสชัน
  • ประหยัด: 85-90%

ที่ราคา $0.0001/1K tokens = ประหยัด $0.0017-0.0018 ต่อเซสชัน

Q: มีโควต้าการใช้งานฟรีสำหรับ Gemini CLI ไหม? ▼

A: มีครับ! โควต้าการใช้งานฟรี:

  • 1,000 requests/วัน ด้วย Gemini 3 (ผสม Flash/Pro)
